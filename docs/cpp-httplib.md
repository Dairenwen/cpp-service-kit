# Cpp-httplib 快速上手

Cpp-httplib 通过单个头文件提供 HTTP 客户端和服务器，支持 HTTP/1.1、持久连接和表单上传。

## 安装与接入

从上游仓库取得 `httplib.h`，将其目录加入编译器的头文件搜索路径。普通 HTTP 示例链接线程库，本仓库通过 `Threads::Threads` 管理该依赖。

补充：开发镜像中的版本为 `0.18.1`，网络 I/O 采用阻塞模型，服务器通过工作线程并发处理请求。[对应版本说明](https://github.com/yhirose/cpp-httplib/blob/v0.18.1/README.md)

| 协议  | 补充：适用场景与依赖                                                                               |
| ----- | -------------------------------------------------------------------------------------------------- |
| HTTP  | 本机或受控网络中的明文联调，使用 `Server` 和 `Client`                                          |
| HTTPS | 需要 TLS 传输加密的接口，启用 `CPPHTTPLIB_OPENSSL_SUPPORT`，链接 `ssl`、`crypto`，并配置证书 |

## 核心类型与接口

| 类型                  | 用途                                   |
| --------------------- | -------------------------------------- |
| `Server`            | 注册请求处理函数，监听地址和端口       |
| `Client`            | 指定目标地址，发送请求                 |
| `Request`           | 保存请求方法、路径、头字段和正文       |
| `Response`          | 保存响应状态、头字段和正文             |
| `Headers`           | 保存 HTTP 头字段                       |
| `Params`            | 保存查询或表单参数，支持同名参数       |
| `MultipartFormData` | 保存表单项名称、内容、文件名和内容类型 |
| `Result`            | 表示客户端取得响应或传输失败的结果     |

`Request` 的常用成员为 `method`、`path`、`headers`、`body`、`params`、`files`、`ranges`、`matches`。其中 `files` 保存上传表单项，`ranges` 保存请求的字节范围，`matches` 保存正则路径匹配结果。

`Response` 通过 `status` 指定状态码，通过 `set_content` 同时设置正文及内容类型，通过 `set_header` 设置头字段；客户端还可读取 `version`、`reason`、`headers` 和 `body`。

## 常规请求

服务器先创建 `Server`，再通过 `Get`、`Post`、`Put`、`Delete` 注册方法与路径对应的回调，最后调用 `listen` 进入服务循环。回调接收请求对象和可写的响应对象。

| 路由形式 | 用途                                |
| -------- | ----------------------------------- |
| 普通路径 | 处理固定地址，如 PDF 中的 `/hi`   |
| 正则路径 | 从路径提取参数，如 PDF 中的数字路径 |

`matches[0]` 是完整匹配，后续元素依次对应正则捕获组。

| 监听地址      | 补充：选择依据                                     |
| ------------- | -------------------------------------------------- |
| `127.0.0.1` | 服务供当前系统内部访问                             |
| `0.0.0.0`   | 在全部 IPv4 网卡监听，供其他机器或 Docker 映射访问 |

补充：监听地址用于绑定本机接口，客户端连接时填写服务所在机器的实际地址。`listen` 返回 `false` 时，应检查端口占用和绑定地址。

## 静态请求

`set_mount_point` 将 URL 路径映射到磁盘目录。PDF 将网站根路径映射到 `webroot`，根路径请求自动查找 `index.html`，随后按文件内容返回响应。

补充：相对磁盘路径以进程工作目录为基准，绝对路径适合由外部启动脚本指定工作目录的场景。挂载接口返回 `true` 后再进入监听流程。

本仓库将页面复制到 `build/bin/webroot`。运行静态示例时，将工作目录设为 `build/bin`，使 `./webroot` 指向对应页面目录。

## 客户端

`Client` 使用服务端地址与端口创建。`Get` 可以附带 `Params` 和 `Headers`；`Post`、`Put`、`Delete` 可以携带正文和内容类型。

| 数据形式                   | 适用内容                               |
| -------------------------- | -------------------------------------- |
| `Params`                 | 查询参数或普通表单，交给库组织参数编码 |
| 字符串正文及内容类型       | JSON、纯文本等报文                     |
| `MultipartFormDataItems` | 带文件名和内容类型的文件上传           |

客户端先检查 `Result` 是否取得响应，再读取状态码及正文。`Result` 成功时，`404` 等 HTTP 错误响应同样可以读取；传输失败时通过 `error` 查看连接或读写错误。

| 状态码                             | 含义                                       |
| ---------------------------------- | ------------------------------------------ |
| `200`、`201`、`204`          | 成功、资源创建成功、成功且正文为空         |
| `301`、`302`、`304`          | 资源重定向或缓存命中                       |
| `400`、`401`、`403`、`404` | 请求格式、身份验证、访问权限或资源定位问题 |
| `500`、`502`、`503`、`504` | 服务端处理、网关、服务可用性或超时问题     |

补充：结束请求后关闭连接时，`Connection` 头的取值为 `close`。

| `set_keep_alive` | 行为与场景                             |
| ------------------ | -------------------------------------- |
| `true`           | 尝试复用连接，适合同一目标上的连续请求 |
| `false`          | 请求完成后关闭连接，适合一次性调用     |

连接复用的持续时间还由服务端策略决定。[客户端连接配置](https://github.com/yhirose/cpp-httplib/blob/v0.18.1/README.md#keep-alive-connection)

## 本仓库示例

在项目根目录执行 `cmake -S . -B build`，再通过 `cmake --build build --target 目标名` 构建。产物位于 `build/bin`。

| 目标名             | PDF 对应内容                    |
| ------------------ | ------------------------------- |
| `httplib_server` | 普通路由和正则路由              |
| `httplib_static` | 静态页面                        |
| `httplib_client` | 携带查询参数与头字段的 GET 请求 |
