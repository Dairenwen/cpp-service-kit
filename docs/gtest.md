# GTest 快速上手

GoogleTest 用断言检查 C++ 程序的行为，并通过测试环境管理准备与清理工作。

## 安装与接入

Ubuntu 开发包为 `libgtest-dev`，头文件为 `gtest/gtest.h`。本仓库链接 `GTest::gtest` 和 `Threads::Threads`，由各示例提供 `main`。补充：采用库提供的入口时，链接 `GTest::gtest_main`。

程序入口先调用 `InitGoogleTest` 解析测试选项，再返回 `RUN_ALL_TESTS` 的结果。测试全部成功时返回 `0`，出现失败时返回 `1`。

## TEST 与 TEST_F

| 宏         | 参数含义             | 适用场景                   |
| ---------- | -------------------- | -------------------------- |
| `TEST`   | 测试套件名、用例名   | 用例直接准备自己的数据     |
| `TEST_F` | 测试环境类名、用例名 | 一组用例复用相同的准备流程 |

`TEST_F` 的环境类继承 `testing::Test`。名称使用 C++ 标识符，套件名与用例名的组合保持唯一。

## 断言如何选择

| 系列         | 失败后的行为                 | 补充：适用场景                       |
| ------------ | ---------------------------- | ------------------------------------ |
| `ASSERT_*` | 立即返回当前函数，并记录失败 | 后续操作依赖当前结果，如迭代器有效性 |
| `EXPECT_*` | 记录失败，继续执行当前函数   | 一次检查多个独立字段                 |

`ASSERT_*` 的影响范围是所在函数。辅助函数中的失败会结束该辅助函数，调用方的后续流程由调用方控制。[断言行为说明](https://google.github.io/googletest/primer.html#assertions)

| 后缀                 | 通过条件                      |
| -------------------- | ----------------------------- |
| `TRUE` / `FALSE` | 表达式为 `true` / `false` |
| `EQ` / `NE`      | 两值满足 `==` / `!=`      |
| `LT` / `GT`      | 左值 `<` / `>` 右值       |
| `LE` / `GE`      | 左值 `<=` / `>=` 右值     |

断言后可追加诊断信息，说明检查目标或当前输入。

## 三层测试环境

| 范围     | 类型或接口                                                                                          | 执行时机与用途                           |
| -------- | --------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| 整个程序 | 继承 `testing::Environment`，实现 `SetUp`、`TearDown`，通过 `AddGlobalTestEnvironment` 注册 | 全部测试前后，适合公共基础设施           |
| 一个套件 | `testing::Test` 中的静态 `SetUpTestCase`、`TearDownTestCase`                                  | 整组用例前后，适合创建成本较高的共享资源 |
| 一个用例 | `testing::Test` 中的成员 `SetUp`、`TearDown`                                                  | 每个用例前后，适合准备可修改的测试数据   |

补充：新版接口名为 `SetUpTestSuite`、`TearDownTestSuite`。套件共享数据通常由静态成员持有，普通成员属于各用例自己的实例。[环境生命周期说明](https://google.github.io/googletest/advanced.html#sharing-resources-between-tests-in-the-same-test-suite)

执行顺序为：全局准备 → 套件准备 → 各用例的准备、测试、清理 → 套件清理 → 全局清理。每个用例都可以单独执行，数据由自身环境准备。

## 本仓库示例

在项目根目录执行 `cmake -S . -B build`，再通过 `cmake --build build --target 目标名` 构建下表中的程序。产物位于 `build/bin`。

| 目标名           | 内容                     |
| ---------------- | ------------------------ |
| `gtest_simple` | 绝对值函数与基础断言     |
| `gtest_global` | 全局测试环境             |
| `gtest_suite`  | 测试套件事件与实例独立性 |
| `gtest_case`   | 每个用例的准备与清理     |
