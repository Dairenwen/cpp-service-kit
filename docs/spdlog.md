# Spdlog 快速上手

Spdlog 通过日志器组织日志，由输出端决定写入位置，支持同步和异步记录。

## 安装与接入

Ubuntu 开发包为 `libspdlog-dev`。主头文件为 `spdlog/spdlog.h`，异步日志使用 `spdlog/async.h`；控制台、普通文件和滚动文件分别使用对应的 `sinks` 头文件。

example使用 `spdlog`、`fmt` 库完成链接，异步模式还使用线程库。本仓库通过 `spdlog::spdlog` 与 `Threads::Threads` 管理依赖。定制版本可从上游源码构建，安装路径由 `CMAKE_INSTALL_PREFIX` 指定。

## 日志等级

| 等级         | 数值 | 用途               |
| ------------ | ---- | ------------------ |
| `trace`    | 0    | 细粒度执行过程     |
| `debug`    | 1    | 开发调试信息       |
| `info`     | 2    | 常规业务事件       |
| `warn`     | 3    | 需要关注的异常征兆 |
| `err`      | 4    | 当前操作失败       |
| `critical` | 5    | 严重故障           |
| `off`      | 6    | 关闭该日志器的输出 |

`set_level` 设置输出门槛，达到该等级及以上的日志进入后续处理。记录错误时调用 `error`，设置错误门槛时使用枚举 `level::err`。

## 输出格式

`set_pattern` 控制整条日志的布局，`set_formatter` 用于配置格式化器。

| 占位符                 | 内容                                  |
| ---------------------- | ------------------------------------- |
| `%Y`、`%m`、`%d` | 年、月、日                            |
| `%H`、`%M`、`%S` | 时、分、秒                            |
| `%t`、`%n`         | 线程 ID、日志器名称                   |
| `%l`、`%-7l`       | 等级名称、左对齐且宽度为 7 的等级名称 |
| `%v`                 | 日志正文                              |
| `%^`、`%$`         | 彩色输出范围的开始与结束              |

正文采用 fmt 的 `{}` 占位语法，参数按顺序填入。补充：日志器的 `set_pattern` 会向全部输出端应用格式；需要各输出端采用专用格式时，最后配置各输出端。[格式定义](https://github.com/gabime/spdlog/wiki/Custom-formatting)

补充：`pattern_time_type::local` 使用本地时间，适合单机观察；`utc` 使用 UTC，适合对齐多台机器的日志。

## 日志器与异步模式

日志器保存名称和输出端列表，并提供 `trace`、`debug`、`info`、`warn`、`error`、`critical` 等记录接口。

| 模式 | 写入方式                           | 补充：适用场景                         |
| ---- | ---------------------------------- | -------------------------------------- |
| 同步 | 调用线程执行输出操作               | 日志量较小，或需要直接观察写入过程     |
| 异步 | 调用线程提交队列，后台线程执行输出 | 日志量较大，希望将写入工作交给后台处理 |

`async_logger` 使用线程池。PDF 通过 `init_thread_pool` 设置队列容量为 `32768`、工作线程为 `1`；线程池应在创建异步日志器前完成配置。

| 队列满时的策略     | 行为与场景                                               |
| ------------------ | -------------------------------------------------------- |
| `block`          | 等待队列出现空间，适合优先保留日志的场景                 |
| `overrun_oldest` | 用新消息覆盖队列中最旧的消息，适合优先保证提交速度的场景 |

补充：单个工作线程按队列顺序处理消息；多个工作线程的完成顺序由调度决定。自定义线程池的生命周期应覆盖使用它的日志器。[线程池与队列策略](https://github.com/gabime/spdlog/wiki/Asynchronous-logging)

## 工厂与输出端

工厂函数默认创建同步日志器，选择 `async_factory` 时创建异步日志器。`async_factory` 采用 `block` 队列策略。

| 工厂函数               | 输出位置             |
| ---------------------- | -------------------- |
| `stdout_color_mt`    | 彩色标准输出         |
| `stderr_color_mt`    | 彩色标准错误         |
| `basic_logger_mt`    | 普通日志文件         |
| `rotating_logger_mt` | 按大小滚动的日志文件 |

输出端对应 `stdout_color_sink_mt`、`basic_file_sink_mt`、`rotating_file_sink_mt` 等类型。Kafka、MongoDB、TCP、UDP 输出端，可按日志接收方选择。

| 输出选项                            | 补充：选择依据                                                                              |
| ----------------------------------- | ------------------------------------------------------------------------------------------- |
| `color_mode`                      | `automatic` 按终端能力显示颜色；`always` 强制颜色；`never` 输出纯文本，适合重定向保存 |
| `_mt` / `_st`                   | 多线程共享输出端选择 `_mt`；整个使用期间由单个线程访问时可选 `_st`                      |
| `truncate=true` / `false`       | 每次打开文件清空旧内容 / 继续追加历史日志                                                   |
| `rotate_on_open=true` / `false` | 启动时先滚动，分开各次运行 / 按文件大小触发滚动                                             |
| `max_file_size`、`max_files`    | 分别限制单文件大小和保留的滚动历史文件数量                                                  |

`_mt` 表示输出端的线程安全属性，同步或异步由工厂决定。最终输出须同时通过日志器和输出端的等级门槛；PDF 的多输出端示例将警告写向控制台，将详细日志写向文件。[输出端说明](https://github.com/gabime/spdlog/wiki/Sinks)

## 全局配置与刷新

`spdlog::set_level` 等全局接口作用于注册的日志器；直接构造的独立日志器通过其成员函数配置。

| 接口            | 用途                                            |
| --------------- | ----------------------------------------------- |
| `flush`       | 请求刷新当前日志器的输出端                      |
| `flush_on`    | 达到指定日志等级时刷新                          |
| `flush_every` | 按时间间隔刷新注册的日志器，适合 `_mt` 输出端 |

补充：异步日志器将刷新请求放入队列，`shutdown` 用于完成后台线程收尾。文件刷新将库缓冲提交给底层输出流，磁盘持久化由系统进一步处理。[刷新策略说明](https://github.com/gabime/spdlog/wiki/Flush-policy)

## 使用样例与组件选择

在项目根目录执行 `cmake -S . -B build`，再通过 `cmake --build build --target 目标名` 构建。`spdlog_multi_sink` 演示两个输出端，`spdlog_async` 演示异步文件写入；产物位于 `build/bin`。

文件日志写入当前工作目录下的 `logs`。日志量较大时，通过等级门槛和滚动文件控制输出规模。
